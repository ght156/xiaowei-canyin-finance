# 小微餐饮财务管理系统

面向乡镇小餐饮店（面食店、早餐店等）的轻量记账与经营分析系统。目标：**简单记账、自动算利润、安全备份、可扩展**。

- 店主在手机上 5～10 秒完成一笔收入/支出记录，支持"再记一笔"连续录入
- 自动汇总今日 / 昨日 / 本月 / 任意区间的收入、支出、利润和利润率
- 多店铺独立核算与合并汇总
- 软删除回收站、操作审计日志、每日自动备份 + 恢复前安全备份 + 备份下载
- PWA 支持，手机浏览器可"添加到主屏幕"

## 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + Vite + Vant 4（移动端优先）+ PWA + ECharts + Pinia |
| 后端 | FastAPI + SQLAlchemy 2.x |
| 数据库 | SQLite（单文件，备份即复制文件） |
| 鉴权 | JWT + RBAC（管理员 admin / 店主 owner） |
| 业务时区 | 统一按北京时间（Asia/Shanghai，`app/tz.py`）计算，部署到 UTC 服务器也不出错 |
| 测试 | pytest 78 个用例，覆盖利润计算、权限校验、时区边界、备份恢复、登录防爆破 |

金额在后端与数据库中一律以 **"分"为单位的整数** 存储与计算，API 层使用两位小数字符串传输，前端汇总同样按"分"做整数运算，全链路杜绝浮点误差。

## 快速开始

### 1. 后端

```bash
cd backend
python -m pip install -r requirements.txt

# 初始化数据库（幂等，可重复执行）
python seed.py

# 启动（默认 http://127.0.0.1:8000）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 2. 前端

开发模式（带热更新，自动代理 /api 到 8000 端口）：

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

生产模式（推荐，手机直接访问后端即可）：

```bash
cd frontend
npm run build      # 生成 dist/
# 重启后端后，直接访问 http://<电脑IP>:8000
```

## 主要功能

- **快速记账**：记收入 / 记支出；金额默认聚焦、数字键盘、分类宫格、默认今天；保存后可选"再记一笔"连续录入（保留店铺/支付方式/日期）；自动记忆上次支付方式；金额 ≥5000 元或选择未来日期时二次确认；30 秒内重复录入相同流水会提示注意
- **流水管理**：按店铺 / 类型 / 分类 / 日期区间（今天、近 7 天、本月、上月、自定义）筛选，切换类型自动清空旧分类筛选；按日分组显示"9月5日 周六 · 收入 ¥xx · 支出 ¥xx"
- **经营分析**：按日 / 按月 / 自定义区间的收入、支出、利润、利润率（收入为 0 显示 "—"）；月度显示营业天数、日均收入、日均利润；收入支出趋势图 + 支出构成（文字列表为主、饼图为辅）；分店铺明细
- **首页经营速览**：今日收入/支出/利润大字显示 + 昨日收入对比（比昨日 +¥xx）
- **店铺管理**：多店铺（默认面食店、早餐店），可新增、停用；记住上次使用的店铺
- **分类管理**：2 类收入 + 15 类支出预置，管理员可新增、改名、停用、排序；停用分类不能再用于新流水，但历史流水完整保留
- **数据安全**：
  - 删除一律软删除，回收站可恢复（仅管理员）
  - 修改 / 删除 / 恢复全部写入审计日志（含修改前后值）
  - 每天第一笔流水自动触发当日备份（不依赖重启），也可手动备份
  - 恢复备份前自动创建"恢复前安全备份"，备份文件经过校验（SQLite 有效性 + 关键表 + 快速完整性检查），失败自动回滚
  - 备份可下载到手机/电脑异地留存
  - 流水导出 CSV（UTF-8 BOM，Excel 直接打开不乱码）

## 利润口径

第一版采用**经营现金口径**：`经营利润 = 区间收入 − 区间支出`，`利润率 = 利润 ÷ 收入 × 100%`。
房租、设备等按实际付款日期计入，不等同于正式会计报表。"营业日"定义为当天存在至少一笔收入或支出流水。

## 数据备份与恢复

- 备份文件位于 `backend/data/backups/`（SQLite 在线备份，复制期间可正常记账），文件名含微秒时间戳，同一秒多次备份不会互相覆盖
- 备份类型：`auto` 每日自动 / `manual` 手动 / `pre_restore` 恢复前安全备份——**各类型分别保留配额**（auto、manual 各 30 份，pre_restore 5 份），手动备份不会挤掉每日自动备份
- 自动备份触发时机：每天第一笔流水 + 每天首次启动，双保险，长期不重启也有每日备份
- 手动备份：我的 → 数据安全 → 立即备份
- **下载备份**：我的 → 备份记录 → 下载（建议定期保存到电脑其他磁盘或网盘，避免单盘损坏）
- 恢复：我的 → 备份记录 → 恢复（**高危操作**：系统恢复到指定时间点，此后的数据可能丢失）。恢复前自动创建安全备份；备份文件经过校验（SQLite 有效性、关键表、完整性检查、**备份内必须仍有启用中的管理员**）；失败自动回滚；恢复成功后自动重建数据库连接，**无需重启服务**

## 生产部署注意事项

1. 复制 `backend/.env.example` 为 `backend/.env`，设置随机 `APP_SECRET_KEY`
2. 前端执行 `npm run build`，之后只需运行后端一个进程
3. 局域网访问：手机与电脑同一网络，访问 `http://<电脑IP>:8000`
4. PWA "安装到桌面" 需要 HTTPS 安全上下文（仅 `localhost` 例外）；局域网 HTTP 下核心功能不受影响但 PWA 能力不可用，详见下方部署方案

### 方案 A：局域网测试版（先用起来）

- 电脑常开，运行 `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`
- 手机浏览器访问 `http://<电脑IP>:8000`
- **能力边界（请如实了解）**：记账、统计、备份等核心功能在局域网 HTTP 下全部可用；但 `http://192.168.x.x` **不是安全上下文，Service Worker / PWA 安装到主屏幕 / 离线缓存等能力通常不可用**（浏览器仅对 `localhost` 例外）。因此方案 A 适合测试与过渡，不适合作为长期正式使用形态

### 方案 B：正式长期使用版（稳定使用必须）

- 部署到一台常开设备（家用旧电脑 / NAS / 云服务器），必须完成：
  - **强制 HTTPS**（Caddy / Nginx + 免费证书均可）——只有 HTTPS 下 PWA 安装、Service Worker、离线缓存才能可靠工作，且密码不明文传输
  - 设置 `APP_ENV=production` 和随机 `APP_SECRET_KEY`（不设置系统会拒绝启动）
  - `APP_CORS_ORIGINS` 限定为实际域名（生产环境禁止 `*`，同样会拒绝启动）
  - 首次初始化用 `SEED_ADMIN_PASSWORD` / `SEED_OWNER_PASSWORD` 设置强密码（生产环境拒绝默认弱密码）
  - 公网部署时登录接口自带防爆破保护（单 IP+用户名 5 分钟内失败 5 次将临时拒绝，仅生产环境启用）
  - 数据目录 `backend/data/` 不放入任何公开静态目录
  - 配置开机自启（Windows 计划任务 / Linux systemd）
  - 定期把 `backups/` 下载到其他磁盘或云盘（备份与数据库同盘只是兜底，不是异地容灾）

## 版本说明

### V1.1.1（当前）

安全与一致性加固（本轮不改业务功能）：

- 备份文件名增加微秒时间戳，同秒多次备份不再可能互相覆盖
- 备份保留策略按类型分别配额（auto / manual 各 30，pre_restore 5），手动备份不再挤占每日自动备份
- 恢复校验升级：备份内必须仍有启用中的管理员，否则拒绝恢复；恢复成功后自动重建 SQLAlchemy 连接池，无需重启
- 回收站接口新增 `deleted_only=1`（只返回已删除流水），前端回收站改用该语义，不再混入正常流水
- 流水/分类接口的 `type` 参数非法值返回 422，不再静默忽略
- 登录防爆破：生产环境单 IP+用户名 5 分钟内失败 5 次后临时拒绝（开发环境不启用）
- 生产环境 `seed.py` 拒绝创建默认弱密码账号，必须通过 `SEED_ADMIN_PASSWORD` / `SEED_OWNER_PASSWORD` 提供
